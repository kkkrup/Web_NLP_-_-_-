## Эндпоинт

**Адрес:** `/api/analyze` (локально: `http://127.0.0.1:8000/api/analyze`; документация сервиса — `http://127.0.0.1:8000/docs`)  
**Метод:** POST

## Запрос

```json
{
  "text": "Вчера вечером я долго разговаривал с преподавателем о будущей работе, и он посоветовал мне обязательно подготовиться заранее. Это было очень полезно.",
  "lang": "ru",
  "mode": "complexity"
}
```

| Поле | Тип | Обязательно | Описание | Ограничения |
|---|---|---|---|---|
| text | string | да | Русский текст, уровень сложности которого нужно определить | От 3 слов до 5 000 символов; не пустой и не из одних пробелов; не менее 50 % букв — русские |
| lang | string | нет | Язык текста | Только `"ru"`; по умолчанию `"ru"`. Любое другое значение даёт ошибку `unsupported_language` |
| mode | string | нет | Режим анализа | `complexity` (по умолчанию) — уровень сложности; `stats`, `freq`, `longest` — учебные режимы курса веб-программирования. Другое значение даёт ошибку `unknown_mode` |

## Ответ при успехе

Ответ состоит из трёх частей: `ok`, `result` (результат анализа) и `meta` (сведения о запросе). Пример для текста из запроса выше в режиме `complexity` (значения `score` и `all_scores` условные, остальные посчитаны по тексту).

```json
{
  "ok": true,
  "result": {
    "level": "B",
    "score": 60.1,
    "all_scores": { "A": 0.001, "B": 0.7862, "C": 0.2128 },
    "factors": {
      "long_sentences": 1,
      "rare_words": 5,
      "syntax_depth": 2.6
    },
    "highlights": {
      "long_sentences": [{ "start": 0, "end": 125 }],
      "rare_words": [
        { "word": "разговаривал", "start": 22, "end": 34 },
        { "word": "преподавателем", "start": 37, "end": 51 },
        { "word": "посоветовал", "start": 75, "end": 86 },
        { "word": "обязательно", "start": 91, "end": 102 },
        { "word": "подготовиться", "start": 103, "end": 116 }
      ]
    }
  },
  "meta": { "chars": 149, "mode": "complexity", "took_ms": 0.4 }
}
```

| Поле | Тип | Описание |
|---|---|---|
| ok | boolean | Всегда `true` в успешном ответе |
| result.level | string | Уровень сложности: `"A"` (A1–A2), `"B"` (B1–B2) или `"C"` (C1–C2) |
| result.score | number | Оценка сложности от 0 до 100, выше = сложнее |
| result.all_scores | object | Вероятности классов: ключи `A`, `B`, `C`, значения от 0 до 1, в сумме 1 |
| result.factors | object | Три показателя сложности (поля ниже) |
| result.factors.long_sentences | integer | Число предложений длиннее нормы; равно длине `highlights.long_sentences` |
| result.factors.rare_words | integer | Число редких слов в тексте; равно длине `highlights.rare_words` |
| result.factors.syntax_depth | number | Упрощённый показатель глубины синтаксиса (чем больше, тем сложнее) |
| result.highlights | object | Что подсветить в тексте (поля ниже) |
| result.highlights.long_sentences | array | Длинные предложения: объекты `{start, end}` |
| result.highlights.rare_words | array | Редкие слова: объекты `{word, start, end}` |
| meta.chars | integer | Число символов в присланном тексте |
| meta.mode | string | Режим, в котором сделан разбор |
| meta.took_ms | number | Время обработки на сервере, мс |

`start` и `end` - позиции символов в исходном тексте (нумерация с 0, `end` не входит в отрезок), то есть `text[start:end]` - это нужный фрагмент. Списки могут быть пустыми. Новые поля в ответ можно добавлять без смены версии, поля из таблицы переименовывать и удалять нельзя.

Функция `analyze(text, mode)` из `nlp.py` (NLP-часть) в режиме `complexity` возвращает ровно объект `result` (поля `level`, `score`, `all_scores`, `factors`, `highlights`). Обёртку `ok` / `meta` добавляет веб-часть (`main.py`).

В учебных режимах `result` устроен иначе: `stats` — `words`, `unique`, `ttr`, `sentences`, `avg_sentence`; `freq` — `top` (список `{word, count}`) и `total_counted`; `longest` — `words` и `max_length`.

## Дополнительные эндпоинты

| Метод и путь | Ответ |
|---|---|
| `GET /api/modes` | `{"modes": ["complexity", "stats", "freq", "longest"]}` — список режимов для выпадающего списка |
| `GET /api/health` | `{"status": "ok", "requests": <число разобранных текстов>}` |
| `GET /api/history?limit=10` | `{"history": [...]}` — последние запросы, новые сверху; `limit` от 1 до 100, по умолчанию 10; другое значение даёт 400 `invalid_request` |

## Ответ при ошибке

```json
{ "error": "text_too_long", "message": "Текст длиннее 5000 знаков", "limit": 5000 }
```

| Ситуация | Код | HTTP |
|---|---|---|
| Пустой текст (или только пробелы) | `empty_text` | 400 |
| Текст длиннее допустимого (больше 5 000 символов) | `text_too_long` | 400 |
| Неподдерживаемый язык (`lang` не `"ru"` или русских букв меньше половины) | `unsupported_language` | 400 |
| Слишком короткий текст (меньше 3 слов) | `text_too_short` | 400 |
| Поле `text` отсутствует, это не строка или тело запроса не JSON | `invalid_request` | 400 |
| Неизвестный режим `mode` | `unknown_mode` | 400 |
| Модель не загрузилась | `model_unavailable` | 503 |

Порядок проверок: сначала формат запроса (`invalid_request`), затем текст — `empty_text`, `text_too_long`, `unsupported_language`, `text_too_short`, затем режим (`unknown_mode`). Если ошибок несколько, приходит первая. Ответ 422 сервис не возвращает: ошибки формата запроса приходят как 400 `invalid_request`, чтобы у интерфейса был один формат ошибок.

Поле `limit` есть только у ошибки `text_too_long` (допустимое число символов). У остальных ошибок только `error` и `message`.

Интерфейс показывает поле `message` пользователю как есть, а по `error` выбирает поведение, если нужно.

## Ограничения

**Максимальная длина текста:** 5 000 символов (примерно 700 слов; в обучающих данных абзацы не длиннее 389 слов).  
**Ожидаемое время ответа:** заглушка - меньше 0,1 с; модель - до 3 с на текст максимальной длины.  
**Нужен ли индикатор загрузки в интерфейсе:** да (модель может отвечать несколько секунд).
