# Реестр рисков

**Срок:** пара 2 · **Обновляется:** на каждой вехе

| № | Риск | Вероятность | Последствия | План действий |
|---|---|---|---|---|
| 1 | Собранных данных меньше расчётного: в readme_ru 1758 текстов, из них на C2 всего 91| Высокая | Модель плохо научится узнавать высокие уровни и будет путать C1/C2 с B2, как Текстометр| Объединить уровни в более крупные группы (например, A, B, C) для минимальной версии проекта; добавить данные из других источников (RuSimpleSentEval, наши 20 текстов); использовать взвешивание классов при обучении|
| 2 | Разметка из источника оказалась недостаточно надёжной: уровень стоит на каждом предложении, а соседние уровни сильно перекрываются| Средняя | 	Модель учится на спорных ответах, качество упирается в потолок, который задаёт сама разметка| Проверить выборку из 50-100 предложений вручную; при оценке качества засчитывать также ответы с ошибкой в один уровень; сравнить с официально заявленными уровнями на наших 20 текстах|
| 3 | Модель не превосходит базовое решение: простая длина предложения уже даёт сильную связь с уровнем| Средняя| Три фактора не оправдывают сложности модели, а результат проекта выглядит слабым| Сразу сравнивать с простым правилом по длине на одной и той же тестовой части; при отсутствии прироста добавить признаки (частотные списки по уровням РКИ, морфология); честно описать результат в карточке|
| 4 | Датасет состоит из отдельных предложений, а не целых текстов| Высокая| Модель, обученная на предложениях, хуже работает на реальных связных текстах, а факторы вроде глубины синтаксиса и длинных предложений на целом тексте считаются иначе| Добавить проверку на целых текстах (наши 20); считать факторы для текста как среднее и максимум по предложениям;|
| 5 | Фактор rare_words слабо различает уровни (rho = 0.121), а списки слов по уровням РКИ неполные| Высокая| Объяснение «редкие слова» на сайте окажется неубедительным, а подсвеченные слова могут быть не сложными (например, уменьшительные формы)| Подобрать порог редкости по данным; использовать частотный словарь с разбивкой по уровням РКИ; ввести правила для уменьшительных форм; при отсутствии улучшения заменить фактор или сделать его вспомогательным|

**Риски, характерные для этих проектов:**

- собранных данных меньше расчётного;
- доля дубликатов и мусора выше ожидаемой;
- источник закрыл доступ;
- разметка из источника оказалась ненадёжной;
- модель не превосходит базовое решение;
- вычислительных ресурсов недостаточно;
- контракт API пришлось менять после написания интерфейса;
- участник команды выбыл;
- модель слишком тяжёлая для публикации.
